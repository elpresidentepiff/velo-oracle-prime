# VÉLØ PIPELINE MAP

This document maps the primary scoring and audit execution flows within VÉLØ Oracle Prime.

## 1. Old VÉLØ Scoring Path (Operational)
The legacy high-conviction scoring lane.

*   **Entry Point:** `scripts/ops/run_prime_today.py`
*   **Execution Chain:**
    1.  **Racecard Load:** `raw_races` loaded from Racing API or local cache.
    2.  **Gate Validation:** `src.velo.racecard_cache_gate.validate_racecard` (Completeness check).
    3.  **Normalization:** `normalize_race(r)` in `workers/racing_api_normalizer.py`.
    4.  **Enrichment:**
        *   **PDF Intelligence:** Pre-loads `data/racecard_merged/racecard_{cc}_{date}.json`.
        *   **RPR Restoration:** Injects real RPR values into the pipeline (authorized 2026-06-03).
    5.  **Service Orchestration:** `score_race_velo_prime()` in `app/services/velo_prime_service.py`.
        *   **Feature Building:** `build_v17_feature_vector()` in `app/services/sqpe_v17_service.py`.
        *   **Win Score:** `predict_sqpe_v17()` (Model: `models/sqpe_v17/sqpe_v17.pkl`).
        *   **Specialist Scores:** `score_runner()` (Models: `models/specialist/*`).
    6.  **Ensemble Assembly:** `VeloPrimeEnsemble.predict_race()` in `src/intelligence/velo_prime_ensemble.py`.
        *   Applies profile weights (`SQPE_IMPROVEMENT_MDS_V1`).
        *   Applies Macro regime context (Chaos damper, etc.).
        *   Computes Playbook G shadow adjustment.
*   **Primary Output:** `data/velo_prime_verdicts_{date}.json`
*   **Observability:** `data/velo_run_observability_{date}.json`

## 2. New Build Two-Lane Path (Challenger)
The high-fidelity feature research and tactical policy lane.

*   **Entry Point:** `scripts/ops/new_build_two_lane_score.py`
*   **Execution Chain:**
    1.  **Feed Retrieval:** Reads `data/new_build/current_cards/current_card_passport_feed_latest.jsonl`.
        *   *Source:* Generated by `scripts/ops/new_build_current_card_feed.py`.
        *   *Passport Intelligence:* Built via `new_build_velo/horse_passport.py` (includes TS features).
    2.  **Two-Lane Scoring:**
        *   **Lane A (Operational):** `core_v0_or_passport_model.pkl` (30 features).
        *   **Lane B (Paper):** `challenger_v1.pkl` (45 features).
    3.  **Feature Mapping:** `_feature_map()` extracts Core, Passport, and Intent features from the feed.
    4.  **Decision Policy V1:** Applies `apply_policy_v1()` in `new_build_velo/policy_v1.py`.
        *   Categorizes runners into: `WIN_TRUST`, `FRAME_TRUST`, `SUPPRESS`, `LOW_DATA`, `NO_EDGE`.
    5.  **Operational Lane Gate:** Selects Lane B only if Intent coverage >= 80%.
*   **Primary Output:** `data/new_build/reports/two_lane_readiness_{date}.json`
*   **Visual Output:** `data/new_build/reports/two_lane_readiness_{date}.md`

## 3. Sigma Audit Path (Truth Loop)
The reconciliation and performance tracking loop.

*   **Entry Point:** `app/pipelines/sigma_runner.py` -> `scripts/ops/run_results_sigma.py`
*   **Execution Chain:**
    1.  **Verdicts Load:** Reads today's predictions from Supabase (or local verdicts).
    2.  **Results Fetch:** Scrapes Racing API finishers for the target date.
    3.  **ID-First Reconciliation:** Matches predictions to results using Race/Horse IDs with course-time fallbacks.
    4.  **Performance Evaluation:** Computes Strike Rate (SR), Frame Rate, and Calibration.
    5.  **Policy Lane Ledger:** Automatically triggers `scripts/audit/build_policy_lane_ledger.py`.
        *   Reconciles Decision Policy tactical lanes against outcomes.
        *   Differentiates confidence: `HIGH_CONFIRMED` vs `MEDIUM_ABSENCE`.
*   **Audit Output:** `data/sigma_results/sigma_results_{date}.json`
*   **Status Artifact:** `data/new_build/summaries/sigma_{date}.json` (Includes Lane Ledger status).

---

## Cross-Dependencies & Data Flows
*   **Shared Raw Source:** Both lanes consume the same `data/racecards_{date}_standard.json` cache.
*   **Ground Truth:** Sigma Audit provides the feedback loop for BOTH Old VÉLØ and New Build lanes.
*   **Tactical Ledger:** New Build scoring outputs the "decisions" that the Lane Ledger reconciles into "evidence".
*   **Model Promotion Gate:** `policy_lane_ledger.jsonl` tracks the n=150 milestone required for New Build lane promotion.
